# 中文模式的屬性頁與地圖英數字（2026-10-26）

使用者要求：使用中文時，屬性頁和地圖註解的英文、數字及符號也使用高解析字型。
沿用目前 HD 字型與設定，不新增開關；使用者已於 2026-10-27 確認 OK。

## 實作

- `STATS.C` 的每筆文字繪製短暫啟用 `port_stats_ascii`。`port_ui_text` 仍優先使用中文姓名、
  原有翻譯與等級格式；沒有翻譯的英文名稱及純數字也可送入既有 HD label。
  每次繪製後立即結束作用範圍，不影響其他頁面的數字。
- 姓名置中；職業和技能名稱靠左；等級、三項屬性、生命／法力、經驗和技能數值靠右。
  沿用原版右界，更新數值時替換既有 label，避免殘留舊位數。
- `map_notes_bridge.c` 在中文模式下，對沒有 `NOTES.UTF` 對應內容的註記直接繪製原有 ASCII 文字。
  使用和中文註記相同的獨立 overlay，繪製及刪除選取使用同一個 HD 字寬計算。
  字型不可用或內容無效時保留原有回退。
- 英文模式的 ASCII 文字維持原版；既有中文姓名、中文地圖註記在英文模式仍正常顯示。
  不改原版數值、輸入、註記文字、存檔格式或翻譯審閱狀態。DOS 分支仍呼叫原版繪字。

## 驗證

- 正常與 UBSan Windows 執行檔編譯通過。
- `test_hd_label.py` 新增實際 `port_ui_text` 與 `STATS.C` 包裝函式測試：語言切換、
  ASCII 作用範圍、靠右／置中、數字位數減少、既有翻譯和中文姓名、無 HD 時回退。
  加入 Windows／Linux／macOS 原生 CI。
- `test_map_notes.py --sanitize` 使用實際 bridge 函式及真正 map-note、overlay、HD layout；
  160 項檢查通過 ASan／UBSan，含舊英數註記、右側邊界、點選字寬、資料不變、
  無字型／無效文字回退、英文模式既有中文旁註。
- 17 個單元測試程式、13 項文字回歸（含 sanitizer、FreeType 與 SDL 視窗合成）、
  portcheck、repocheck、原始碼 ASCII 與交接副本一致性檢查通過。
- 正常與 UBSan 遊戲實景：中英文屬性頁、沒有旁註檔的舊英數地圖註解、刪除後重新開圖。
  中文畫面英文姓名及所有屬性／技能數值均為 HD，英數註記保持文字和座標，未新增旁註檔。
- 中文模式新輸入純英數及中英混合註解，關閉再開啟地圖後驗證原有 ASCII／旁註保存流程。
  輸入以既有 OS 文字提交測試替身提供，未重新驗證實體中文輸入法。
- 16 個公開 session × 中英文及顯示功能開關四種模式：有效存檔資料一致，英文關閉模式與 DOS golden
  原始位元組相同。沿用 `P13_CHEATS.md` 已說明的唯一例外：地圖 ATM 文字第一個 NUL 後的
  未使用填充可能受原版畫面殘值影響；另存原始雜湊，只在額外語意比較中歸零這段填充。
  不宣稱所有模式的原始存檔位元組完全一致。

實際截圖及情境結果：`build/i18n/stats-ascii/`，存檔比對 `replays/report.json`。
本機工具：`.poc-tools/stats-ascii-check.py`（可加 `--debug`、`--entry`）、
`stats-ascii-regression.py`。全部情境使用獨立存檔副本。
本機 DOS 重編譯 Gate 仍缺 Node.js，未驗證。

## 2026-10-31 擴大到所有介面英數字（使用者要求，UW1 與 UW2 一致；同日使用者已確認 OK）

使用者看到 UW2 屬性頁的數字仍是點陣字，要求「中文模式時，英數文字盡量都用高解析中文字型呈現，UW1、UW2 都一樣」。

- `port_ui_text`：中文模式下，沒有譯文的字串只要是可列印 ASCII（0x20～0x7E）就以原文交給 HD 標籤；
  含遊戲自己高位元字元的字串仍用原版點陣字。英文模式不變。原本 `STATS.C` 的作用範圍（`port_stats_ascii`）因此不再需要，保留為無作用的函式。
- 涵蓋 `string_to_screen` 畫的所有英數：屬性頁、人物欄負重、存檔清單、玩家英文姓名、數量與其他介面數字。
  對齊沿用各處既有的 `hd_label_align`（靠右的數值、置中的標題）。
- `stats_ascii_test.c`、`test_hd_label.py` 改為驗證新規則（不限屬性頁、高位元字元保留點陣）。
